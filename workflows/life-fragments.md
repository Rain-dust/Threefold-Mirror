# Low-friction use: Capture / Check-in / Reflection

## Capture — “三世镜，记一下……”

Preserve actual user words with `capture --statement <words>`. Use `--on` only for a known occurrence date; absent date stays unknown. Choose a `fragment_kind` semantically: event, observation, state_evidence, interest_signal, decision_context or consumption. These are retrieval aids, not new epistemic authorities: a Fragment remains **self_report**. Users do not need to know the schema or write a formal diary.

What happened, read, watched, built, noticed or discussed can be useful evidence of current attention. One novel, anime, article, video, research topic or GitHub project cannot establish a stable value. Do not infer that consuming a work implies endorsing it. Record uncertainty and time scale before proposing a State revision. Capture alone creates no State/Pattern automatically.

An explicit choice in an existing Decision uses its separate choice Event with option/action/review links; a Fragment about considering a choice is only context. Do not invent a choice from interest or treat a plan as completed action. Preserve a fragment even when interpretation is not yet useful.

## Check-in — “看看我最近状态”

Read `model`, private recent Fragments and authorized `recent` / `retrieve` candidates first. Distinguish current, decayed, expired, corrected and stale-source assertions. Ask only a small number of useful missing details, one at a time. An unknown energy level is not “normal energy”. A time-limited source that skips undated files is an explicit coverage gap.

Use new testimony or primary evidence to append justified State revisions, with direct citations and new review/expiry dates. Trend needs a comparison. No changes or insufficient evidence may warrant no model revision. Explain the useful update and what remains unknown.

## Reflection — “复盘一下这件事”

First identify what actually happened, what was chosen, and what is only interpretation. If an existing Decision/Simulation exists, preserve the [Outcome → Reflection → model](reflection-correction.md) links and distinguish simulation influence from causality. If no prior decision exists, capture the actual event/result as a Fragment or experience Event, discuss a provisional lesson, and append evidence-backed updates when warranted; do not fabricate a retrospective Decision/Simulation just to fill a graph.

Lessons remain observations/inferences/hypotheses with alternatives and confidence. New State evidence cites the actual outcome or user words, not the Agent's Reflection. Correction always remains available.
