# Mirror Memory and Evidence data contract · v1

Life Sources belong to the user; Mirror Memory belongs to an independent Personal Instance outside Public Core and outside Git repositories. Core accepts the `EvidenceSource` interface; it neither discovers sources nor knows their software. Only `adapters/local-markdown.ts` resolves local source paths. Ordinary Markdown (including an explicitly authorized Obsidian folder) needs no migration. Dates come from `occurred_at`, `date`, `observed_at`, `created_at`, then YYYY-MM-DD filename; never filesystem mtime. Unknown date stays unknown. Invalid source YAML is reported as a warning; invalid Memory records stop loading. See [source consent](source-consent.md) for time-limited read rules.

| Type / folder | Durable meaning |
| --- | --- |
| event / Events | Actual testimony about experience, explicit choice or intervention. A plan remains a plan. |
| state / States | One dated, revisable assertion about a state key. |
| pattern / Patterns | A revisable interpretation with alternatives and a falsification question. |
| decision / Decisions | Question, alternatives, constraints, resources, review date. |
| simulation / Simulations | Conditional branches from a specific model and Decision. |
| outcome / Outcomes | Actual result linked to Decision, choice, simulation and interventions. |
| reflection / Reflections | Comparison and lessons with direct Outcome evidence. |
| correction / Corrections | User correction of a State/Pattern; immediately invalidates it. |
| life_fragment / LifeFragments | Actual user words, optionally answering an Interview; event, state, interest, consumption or decision context without diary ceremony. |
| interview_turn / Interviews | One Agent-selected question, gap, reason, domain and links to prior answers. |
| prior_self_knowledge / PriorKnowledge | User-supplied derived model; original text and provenance, never raw fact or corroboration. |
| self_model / SelfModels | v0.1 summary, all current assertion refs, prior refs, domain coverage, explicit unknowns/contradictions; optional calibration_focus selects high-impact references for initial feedback. |
| calibration / Calibrations | Progressive actual feedback on one or more reviewed claims/priors; disputed or uncertain items link preceding Corrections. Accumulated feedback on the selected focus completes initialization. |

Every record has `schema_version: 1`, unique ID, type, title, UTC `created_at`, `authored_by`, `data_origin`, source period, evidence and counter-evidence. `data_origin` is real or fictional; fictional evidence cannot support a real record. `authored_by: user` means actual testimony, not an Agent assigning this label to its own theory. The CLI cannot authenticate authorship; this is an Agent responsibility.

`created_at` is when knowledge was recorded. Historical time belongs in `source_period`/`occurred_at`. Strictly increasing write timestamps prevent retroactive contamination of old simulations. Use UTC ISO instants with milliseconds; local event dates and expiry use ISO calendar days. No timezone is inferred from a filename.

Files live at `<personal-instance>/ThreefoldMirror/<folder>/<id>.md`; internal record links use full instance-relative wikilinks. External Evidence uses `source_id` plus an adapter-owned opaque `source` locator. Without `source_id`, `source` must resolve within Memory (or the explicitly fictional legacy harness). Every citation retains exact quote, SHA-256, original lines and time period. Source content is loaded on demand in memory, not mirrored wholesale. Frontmatter contains structured fields. Markdown repeats any `statement` verbatim, presents Self Model summary, and preserves calibration feedback. Contradictory body edits are not revisions.

New IDs publish complete files atomically by same-volume hard link. Same ID/content is a no-op; differing content is rejected. Revisions use `supersedes`; Correction uses `target`; corrected revisions link both the prior record and Correction. Nothing deletes the predecessor.

The writer uses `ThreefoldMirror/.write-lock/`. If a crash leaves it, verify no writer is active, remove only the empty lock directory, then retry the same ID. No automatic lock stealing. This is a cooperative local writer protocol, not protection against hostile concurrent filesystem mutation. Filesystems without hard-link support fail safely without a partial publish.

Multi-record workflows commit one valid record at a time. After Correction, the old state is already invalidated even if the replacement fails. After Outcome, reality is saved even if reflection fails. Resume missing work using existing IDs. Symlinks/junctions, escaping paths and overwrites are rejected. Hidden directories are skipped. Scan limits: 10,000 notes/directories, 2 MB per note, 100 MB total; exceeding a limit fails clearly.

`model` reconstructs State/Pattern projection and history; `start` reconstructs bootstrap state from private records without contacting sources. The state machine is interview → calibration → ready. A structurally valid, substantively limited Self Model draft changes the phase to calibration. Unknown domains may remain unknown. Decision/Simulation writes require ready in production. A new draft requires another calibration. `rebuild` optionally writes `<instance>/.mirror-cache/index.json`. No command reads that cache as authority; deleting it loses no information. A revoked, narrowed, missing or changed external source removes dependent assertions from the current projection; historical quotes remain in private records. Revocation does not erase past records or imply that a retained quote remains currently authorized for retrieval.

`calibration_focus` is an optional nonempty, unique subset of assertion_refs + prior_refs, selected before feedback (usually 2–4 important judgments, not a quota). Omission preserves Phase 2's all-references requirement. Calibration records may contain any nonempty subset of reviewed references with no duplicates within a record; multiple records for one model are allowed. A repeated target in a later record preserves changed feedback; `start` exposes the latest response. All actual feedback remains immutable. Only cumulative feedback on the latest model's focus makes it ready; responses to older drafts do not transfer. Unselected/unanswered claims remain explicitly unreviewed. A non-correct response still requires its preceding Correction, including not_sure. Ready means initial feedback was obtained, not that every judgment was confirmed or that unknowns were resolved. Later correct feedback never revives a corrected assertion; a grounded revision is required.

Human Map, interview stage/mode, evidence diversity and cognitive effort are semantic workflow decisions, not additional record types. Record concise next-question rationale in interview_turn.reason and private working notes. Unknown/skip/difficult answers are ordinary life_fragments and clear a pending question; silence does not. The 15 coverage entries are storage compatibility, never mandatory interview coverage. Channels, transitions, Knowledge/Experience/Skill, conditional regression and core tension reuse scoped State/Pattern with the original epistemic and temporal rules; see [Interview Model](../INTERVIEW_MODEL.md).

Prior-supported State/Pattern uses `prior_refs`, inference/hypothesis, low/unknown confidence and a temporary scale. It does not increment independent evidence counts. Direct evidence must support stronger claims; append a new revision without the prior dependency when justified. Correcting/superseding a prior immediately invalidates its dependent claims. Prior revisions preserve originals; weakened confidence must decrease, and corrected revisions link the user's Correction. `correct` calibration records testimony, not independent verification or automatic confidence promotion.

JSON Schema is generated from `core/schema.ts`. Other runtimes can implement this protocol. Schema validation alone cannot enforce chronology, evidence hashes, model fingerprints, expiry or graph integrity: use the CLI or reproduce those checks. Unknown schema versions fail; future migration must be explicit and confined to framework records.
